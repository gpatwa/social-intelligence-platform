# Interoperability contract registry

This registry is the stable boundary between collectors, the Databricks data
plane, decision services, agents, and external consumers. Contract changes are
additive within a major version. Breaking changes require a new file and a
migration plan; published versions are never rewritten in place.

| Contract | Purpose | Current version |
| --- | --- | --- |
| Connector landing envelope | Durable, replayable ingestion record | [`v1`](../schemas/social-event-envelope-v1.json) |
| CloudEvents mapping | Standards-based event transport | [`v1`](json-schema/cloud-event-social-event-v1.json) |
| CloudEvent data | Source payload and attributes | [`v1`](json-schema/social-event-data-v1.json) |
| Evidence | Provenance and trust reference | [`v1`](json-schema/evidence-v1.json) |
| Agent artifact | Reviewable agent output, without hidden reasoning | [`v1`](json-schema/agent-artifact-v1.json) |
| Opportunity | Prioritized commercial signal | [`v1`](json-schema/opportunity-v1.json) |
| Recommendation | Governed action proposal | [`v1`](json-schema/recommendation-v1.json) |
| Experiment plan | Measurement gate for an approved action | [`v1`](json-schema/experiment-plan-v1.json) |
| Ranked evidence | Explainable, decision-specific source ranking | [`v1`](json-schema/ranked-evidence-v1.json) |
| Recommendation context request | Bounded inputs to compile a batch-reranking context | [`v1`](json-schema/recommendation-context-request-v1.json) |
| Recommendation context | Deterministic evidence, business, candidate, and outcome packet | [`v1`](json-schema/recommendation-context-v1.json) |
| Internal pilot request | Bounded staging discovery inputs | [`v1`](json-schema/internal-pilot-request-v1.json) |
| Internal pilot plan | Seven-day plan, workflow, controls, and scorecard | [`v1`](json-schema/internal-pilot-plan-v1.json) |
| Consumer API | Read/propose API boundary | [`v1`](openapi/social-intelligence-api-v1.yaml) |

CloudEvents describes **what happened**. OKF describes **what the concepts and
computations mean**. MCP is the current agent adapter; A2A and AG-UI remain
future adapters around these durable contracts, not replacements for them.

## Compatibility policy

- Producers may add optional fields only when consumers ignore unknown fields.
- Required fields, identifiers, enum semantics, and units are immutable in v1.
- The existing Databricks landing record remains the source of truth.
- CloudEvents is an adapter generated by `SocialEventEnvelope.to_cloudevent()`.
- Agent outputs contain claims, evidence references, confidence, and risks—not
  chain-of-thought or provider-specific message history.
- MCP tools must use these contracts through a tenant-scoped provider; they may
  read or draft, but never approve spend or mutate lifecycle state directly.
- `recommendation-context-v1` is context preparation only: it may constrain a
  future model ranker, but it cannot invoke a model, invent candidates, retrieve
  external data, claim causality, or make an external change.
